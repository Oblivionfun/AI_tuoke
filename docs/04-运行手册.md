# 运行手册

## 1. 本地试用（10 分钟）

```bash
uv sync
cp .env.example .env              # 填 OPENAI_API_KEY；本地把 WB_COOKIE_SECURE 改成 false
uv run workbench init --admin 张三  # 建表、导入样册（84 张产品卡、6 家候选）、创建账号
uv run workbench demo seed        # 可选：载入演示数据（阿联酋 / 南非 / 沙特的真实客户档案）
uv run workbench doctor --live    # 体检：提示词、知识包、真实调用一次模型和联网搜索
uv run workbench serve            # 网页 http://127.0.0.1:8000
uv run workbench worker           # 另开一个终端：执行网页上排队的任务
```

不开网页也能跑：`uv run workbench prospect --country AE --group 自钻螺钉 --count 5 --now`，终端里会实时打印每一步。

## 2. 部署到新加坡 VPS

推荐 2 核 4G、Ubuntu 24.04，装好 Docker。

```bash
git clone <仓库> /opt/guanwei-workbench && cd /opt/guanwei-workbench
cp .env.example .env              # 填 OPENAI_API_KEY、DOMAIN、WB_SESSION_SECRET（随机长字符串）、签名信息
docker compose build
docker compose run --rm web workbench init --catalog /app/seed/guanwei_catalog.sqlite --admin 张三
docker compose run --rm web workbench sanctions-update   # 下载制裁名单（只做提示）
docker compose up -d
crontab -e                        # 加一行：0 3 * * * cd /opt/guanwei-workbench && ./deploy/backup.sh >> data/backup.log 2>&1
```

- 域名的 A 记录指向 VPS，Caddy 会自动申请 HTTPS 证书。
- 三个服务：`web`（网页）、`worker`（执行 agent）、`caddy`（HTTPS）。数据都在 `./data`。
- 升级：`git pull && docker compose build && docker compose up -d`。数据库迁移在启动时自动执行。
- 恢复备份：停服务，把 `data/backups/workbench-*.db` 复制为 `data/workbench.db`，再启动。上线前演练一次。

### 合规要求：公网访问和模型网关

- **不要用 cloudflared、frp、ngrok、SSH 反向隧道等方式把公司设备或公司内网服务暴露到公网**，也不要把公司内网的模型网关（AIHub）转发给外部服务器。公司安全会检测并要求关闭，这类方式之前用过，已全部撤掉。
- 只给公司同事用：部署到 with 平台（https://with.woa.com/）并接入太湖身份鉴权，机器在内网，直接访问 AIHub，不需要任何转发。
- 给外部客户用：部署在外部服务器上，开放服务器自己的端口或绑定域名（用上面的 Caddy 配 HTTPS），模型换成外部的服务（例如海外服务器直连 OpenAI），改 `.env` 里的 `WB_LLM_*` 或 `OPENAI_API_KEY` 即可，代码不用动。公司 AIHub 的 key 不要放到外部服务器上。

## 3. 日常使用（业务员）

1. **早上**：打开"今日审核"，最多 10 张卡。每张先看结论、对得上的产品、怎么联系、要注意的风险；正文里的小编号是来源，鼠标移上去能看到网址。然后决定：
   - 接受（键盘 A）：文案 agent 几十秒后写好草稿；
   - 补证（E）：写清楚要补什么，系统退回调研；
   - 不合适（X）：选一个常用原因或自己写，归档。
   决定后自动跳到下一张。J / K 上下切换，? 查看全部快捷键。
2. **发信**：在客户档案的"草稿"页改好草稿，点"复制主题和正文"，从公司企业邮箱发出，回来点"我已从企业邮箱发出"。"跟进"页的左栏列出所有待发送的草稿。
3. **跟进**：对方回复后在客户档案的"跟进"页记一笔。对方加了 WhatsApp，报价、打样转到 WhatsApp。对方问价就点"新建报价"。
4. **报价**（侧栏"报价单"，任何客户都能报）：
   - 先在产品库给常卖的产品填一次"规格与价格"：英文规格、计价单位、参考价、成本。样册里没有的产品点"新增产品"。
   - 新建报价：输入客户名（已有客户会提示）；在"搜产品"里点一下加一行；每行填尺寸、数量、单价。单价默认是上次报给这个客户的价，没有就用参考价。
   - 客户发来一大段询价时，展开"粘贴客户发来的询价"，贴进去点"AI 拆分"，十几秒后明细自动出现，页面上会列出还要向客户确认的问题。AI 不填价格。
   - 条款默认收起（币种、贸易术语、有效期、付款方式），要改时点"修改"。
   - 点"生成报价单 PDF"，浏览器直接下载英文报价单，从 WhatsApp 或邮件发给客户。改价后再生成就是第 2 版，每一版都能在右侧重新下载。
   - 毛利按产品库里的成本自动算，低于目标（`WB_QUOTE_TARGET_MARGIN`，默认 18%）显示琥珀色，请老板确认。成本不会印在报价单上。
   - 客户回复后在右侧点"成交"或"未成交"（可以选原因）。
5. **对方说不要再联系**：点"加入拒绝联系名单"，以后寻客不会再出现，也不能再报价。
6. **运营**：在"运行"页按"国家 + 产品组"发起寻客，或者粘贴几个官网网址直接调研。

## 4. 每周提示词复盘（运营 / 技术）

1. 在"客户队列"筛出被驳回（不合适、补证）的卡片，打开"运行记录"里的 trace 链接，看 agent 在哪一步走偏。
2. 修改 `prompts/*.md` 或 `knowledge/*.md`。改契约时把第一行的版本号加一（例如 `researcher-v2`）。
3. 在评测集上前后各跑一次并对比：
   ```bash
   uv run workbench eval run                    # 改之前（或用上次的报告）
   uv run workbench eval run                    # 改之后
   uv run workbench eval compare eval/reports/eval-A.json eval/reports/eval-B.json
   ```
4. 指标没有变差再上线（`git pull` 后重启 web 和 worker）。评测集的人工标注在 `eval/golden.yaml`，核对过的样本把 `verified` 改为 `true`。
5. 评测集稳定后，再逐个环节试降模型：例如 `WB_MODEL_WRITER=<便宜型号>`，跑评测，对比效果和花费。

## 5. 名单对比（演示用）

```bash
uv run workbench eval baseline eval/llm_memory_baseline.yaml
```

检查"直接问聊天机器人"得到的名单：官网能不能打开、邮箱能不能在官网上找到，生成 `eval/reports/baseline-compare.md`。如果要用 ChatGPT 网页版的真实回答，把它整理成同样格式的 YAML（`source`、`items[]` 里有 `country`、`name`、`website`、`email`）再跑一次。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 运行失败 "Missing credentials" | `.env` 里没有 `OPENAI_API_KEY`，填好后 `docker compose up -d` |
| 运行失败 "超过最大轮数" | agent 在一家公司上搜索过多。调大 `WB_MAX_TURNS_RESEARCHER`，或在提示词里收紧步骤 |
| 今日审核没有卡片 | 队列空了，去"运行"页发起寻客；或者调研都判定为不合适，看"客户队列"里的已归档 |
| 运行页一直"等待 worker 接手" | worker 没在运行：`docker compose ps`、`docker compose logs worker` |
| 花费偏高 | 运行页看每家的搜索次数；先降 `WB_SEARCH_CONTEXT_SIZE`，再试降审查或文案的模型 |
