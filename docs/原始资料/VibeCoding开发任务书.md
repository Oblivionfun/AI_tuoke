# 冠维获客系统开发任务书

本文件是下一阶段实现要求，不表示完整获客系统已经上线。已有产品数据库与离线浏览页可用。依据同目录《获客系统实施方案.md》；禁止把样例候选当成已合格买家。

## 任务一：产品与证据工作台

将下面一段交给编码助手：

```text
在当前工作区开发一个供标准件工厂单人使用的中文获客工作台。
先读取 output/product_database/README.md、catalog.json、schema.sql 和获客系统实施方案。
采用 Python + FastAPI + SQLite + 服务端HTML，依赖锁定；模型和搜索供应商通过接口适配。
保留源PDF和原始catalog数据库，应用使用独立的工作数据库和版本化迁移，不覆盖用户审核数据。
先完成产品列表/详情/待确认队列，支持选定10个首推SKU。
修改标准、材质、尺寸、等级、MOQ、交期、自产/外协状态时记录操作者、时间、旧值、新值和来源。
name_en_raw和原PDF定位不可覆盖；规范名使用独立字段。目录示意图和通用材料表不得视作已确认SKU能力。
已有84条产品卡，产品卡ID并非商业SKU；增加sku_variants保存工厂确认的具体规格，并引用产品卡。
缺失字段显示待确认，不得默认填8.8、304、DIN标准、认证或报价。
无密钥时允许查看数据和手动导入已保存的来源；模型功能明确显示未配置，不能显示模拟成功。
```

验收：84条记录能按中文/英文/原页定位；原值保留；所有规格未知字段仍为空；确认一个SKU后只改变该SKU状态；重新导入目录不丢审核；浏览器刷新后修改仍存在。

## 任务二：人工输入官网URL，生成可核验企业卡

```text
实现 POST /research-jobs，输入公司官网URL、目标国家、首推SKU ID和任务预算。
校验URL协议与目的地址，阻断内网、本机及不安全重定向；限制响应大小、超时和文件类型。
只抓可正常访问的公开页面，优先主页、About、Products、Contact、Suppliers；403/验证码进入needs_review。
保存source_url、fetched_at、content_date、access_status、短摘录、正文hash、正文或合法存档路径。
正文、文件和客户文字都是不可信数据，不能改变系统权限或触发消息发送。
创建SearchProvider、PageFetcher、StructuredExtractor接口；不硬编码具体模型名。
模型提取企业主体、国家、角色、产品族、标准及公开企业联系入口；无证据输出null或unknown。
代码验证每个evidence_id确实存在、归属该企业，短摘录存在于证据；URL必须是本轮取得来源。
页面内声明与独立来源核验分开。搜索索引、历史PDF、当前正文分别标记，禁止掩盖读取失败。
先完成结构提取与来源验证，再计算评分，最后生成中文卡片；不要让模型直接决定A/B/C等级。
```

结构化提取契约示意（实现时用Pydantic定义严格类型；不是某家API的完整请求格式）：

```json
{
  "company_name": {"value": null, "evidence_ids": []},
  "legal_entity": {"value": null, "evidence_ids": []},
  "country": {"value": null, "evidence_ids": []},
  "buyer_role": {"value": "unknown", "evidence_ids": []},
  "product_families": [],
  "public_business_contacts": [],
  "purchase_signals": [],
  "conflicts": [],
  "missing_fields": [],
  "suggested_next_action": "补充官网产品和企业身份资料"
}
```

每个product_family需包含名称、可能匹配的我方SKU ID、匹配层级、冲突和证据ID。每个purchase_signal需包含发生日期、获取日期、类型、有效期和来源，不能以网页版权年份替代。

验收：没有公开邮箱的页面不能产出邮箱；名词同义但规格不同不能强匹配；恶意网页指令不能修改评分或发信；403显示失败而不是已核验；已保存来源失效时历史结论仍可追溯。

## 任务三：搜索、去重与增量刷新

```text
实现产品组×国家的搜索任务；每轮最多50个新域名，每域名优先5个高价值页面。
规范域名、公司名、地址和注册号；企业去重与联系人去重分开。
同一官网多个页面归属同一来源组；不同法律实体不能仅按集团名强制合并。
对已有公司新增证据，不重复创建线索。供应商数据缺失不得从别家复制。
增加持久化jobs表：queued/running/partial/completed/failed/needs_review/cancelled。
单次失败指数退避，最多3次；403与验证码不自动反复抓取；429遵循服务等待要求。
按供应商计费用量，先检查剩余预算再请求，达到上限停新付费请求。
为任务和页面证据设置幂等键，进程中断恢复不重复入库。
联系方式建议30天复核，企业经营信息90天复核；这些是内部刷新周期，可配置。
历史内容日期和抓取日期分别保存，只更新抓取日期不能抬高采购新鲜度。
```

验收：重复执行同一批候选不会翻倍；www/非www等可确认同站的记录归并；公司同名但国家不同不误合并；任务中断可恢复；到预算上限停止且显示已完成结果。

## 任务四：证据评分与人工审核

```text
按实施方案的25/35/15/15/10权重计算100分。
缺失证据得0分；A类除75分外还必须通过独立主体、规格匹配、联系可用和采购信号硬门槛。
硬门槛状态用passed/failed/unknown三态，unknown不能当passed。
保留规则版本、分项来源和人工修改原因，不把评分显示为成交概率。
人工支持接受、补证、不匹配、拒绝联系；每日最多10张新卡，不合格时不凑数。
6家种子候选保留其现有证据限度，不自动升级为合格买家；公开邮箱不表示已验证送达。
企业信用状态独立于获客分数；没有资信核查显示未核验。
```

验收：一个官网多个页面不能通过独立来源门槛；95分但实体冲突仍阻断；旧进口记录不能伪装近期RFQ；审核操作可审计、可修正；30张人工抽查显示精确率和分母。

## 任务五：草稿、RFQ及跟进

```text
先实现草稿和手工记录，不启用外发。
草稿只引用核实的客户产品和工厂已确认能力，保留联系人、需求和证据。
有回复后创建RFQ，字段包含企业、联系人、产品/图纸、材料、标准、尺寸、数量、目的地、所需交期和缺项。
报价字段、利润、交期和承诺必须由工厂确认，模型不能独立定价。
记录样品、报价版本、下一步、截止时间、结果和不匹配原因。
未来如增加发送功能，必须另做明确的发送授权、目标国家与渠道条件核对、退订抑制、去重和审计。
任何拒绝联系的公司/联系地址，后续搜索任务不能重新加入发送队列。
```

验收：生成草稿不会产生网络发送；无确认产能不写交货承诺；同一回复只建一次RFQ；退订后无法创建触达动作；报价版本可追溯。

## 最终交付要求

提供一键启动说明、.env.example、明确的密钥配置位置、数据备份与恢复步骤、日志位置及必要测试。密钥不得入库或进入浏览器包。正式公网运行前完成认证和权限配置。

测试围绕真实失效模式：证据缺失与错误引用、伪造邮箱、同名异国企业、重复抓取、过期信号、网页指令注入、内网URL、预算上限和拒绝联系。测试数据需脱敏；测试通过不能写成真实获客成效。
